ct-replica 1. ใช้งานประจำวัน 2. วันฉุกเฉิน 3. เจอแบบนี้ทำยังไง

คู่มือใช้งาน ct-replica

ทำสำเนา CT ไปเก็บที่เครื่อง backup อัตโนมัติ — ฉบับใช้งานจริง อ่านรอบเดียวทำได้เลย

ทุกคำสั่งพิมพ์บนเครื่อง {nfs_node} ยกเว้นข้อที่บอกไว้ชัดๆ
0

มันทำอะไรให้เรา

ทุก 15 นาที โปรแกรมจะ copy ข้อมูลของ CT ที่เราสั่งไว้ ไปเก็บเป็นสำเนาบนเครื่อง {backup_node} สำเนาทุกตัวถูกปิดไว้ตลอด (เลขจะเป็น 8xxx เช่น CT 105 → สำเนา 8105) วันไหนเครื่องจริงพัง ค่อยไปเปิดสำเนาใช้แทน

ปลอดภัยกับ CT จริง 100% โปรแกรมอ่านอย่างเดียว ไม่แตะ ไม่ปิด ไม่ทำให้ช้า CT ของลูกค้าทำงานตามปกติตลอดเวลา

เข้าโฟลเดอร์โปรแกรมก่อนเสมอ

$ ssh root@{nfs_node}
$ cd /root/tp
ส่วนที่ 1

ใช้งานประจำวัน

1

ไฟล์ที่ต้องรู้จัก มี 3 ไฟล์

ไฟล์คืออะไรต้องแก้ไหม
ct-replica.shตัวโปรแกรมไม่ต้องแก้เด็ดขาด
inventory-migrate.tsvรายชื่อ CT ที่จะทำสำเนาแก้บ่อยที่สุด
ctrep.confตั้งค่า (ความเร็ว, ปลายทาง)ตั้งครั้งเดียวจบ

โฟลเดอร์ logs โปรแกรมสร้างเอง ไม่ต้องไปยุ่ง

2

inventory-migrate.tsv — บอกว่าทำสำเนาตัวไหน เก็บชั้นไหน

หนึ่งบรรทัด = CT หนึ่งตัว ช่องแรกคือเลข CT จริง ที่เหลือใส่เท่าที่ต้องใช้

105   ssd                  # important customer -> fast tier
112   hdd                  # ordinary customer -> ordinary tier
113                        # nothing named = ordinary tier
120   9120  ssd            # pick the copy id by hand (rarely needed)
สิ่งที่ใส่ความหมาย
ssd หรือ hddชั้นเก็บสำเนา — ssd = กู้คืนไว สำหรับลูกค้าสำคัญ · hdd = ชั้นธรรมดา
เลขตัวที่สองเลขสำเนาแบบกำหนดเอง — ปกติไม่ต้องใส่ โปรแกรมใช้ เลขเดิม+8000 ให้เอง

กฎ 2 ข้อ

  • เลข CT ห้ามซ้ำกัน ถ้าซ้ำ โปรแกรมจะไม่ยอมทำอะไรเลยทั้งไฟล์ แล้วบอกว่าซ้ำที่บรรทัดไหน แก้แล้วรันใหม่
  • ห้ามเปลี่ยนชั้น (ssd↔hdd) ของตัวที่มีสำเนาแล้ว โปรแกรมจะหยุดและไม่ยอมทำตัวนั้น — ถ้าต้องย้ายชั้นจริงๆ ให้เรียกผู้ดูแลระบบ

บรรทัดที่ขึ้นต้นด้วย # คือคำอธิบาย โปรแกรมข้ามให้ ใช้พักบรรทัดที่ยังไม่อยากให้ทำงานได้

3

คำสั่งที่ใช้จริง มี 3 แบบ

$ ./ct-replica.sh
$ ./ct-replica.sh --storage tank-ssd-nas
$ ./ct-replica.sh --ctid 105
คำสั่งทำอะไร
./ct-replica.shทำทุกตัวในรายชื่อ
--storage ...ทำเฉพาะ CT ที่ข้อมูลอยู่บน storage นั้น (แบบเดียวกับที่ cron รัน)
--ctid 105ทำเฉพาะตัวเดียว — ใส่เลข CT จริง ไม่ใช่เลขสำเนา

ปกติไม่ต้องรันเองเลย cron รันให้ทุก 15 นาทีอยู่แล้ว รันมือเฉพาะตอนเพิ่ม CT ใหม่ แล้วอยากเห็นผลทันที หรือตอนไล่ปัญหา รันซ้ำได้เรื่อยๆ ไม่มีอันตราย แต่ละรอบ copy เฉพาะส่วนที่เปลี่ยน

4

ดู log

log อยู่ในโฟลเดอร์ logs แยกไฟล์ต่อวันต่อสาย

$ tail -f logs/$(ls -t logs | head -1)

ออกจากหน้านี้ด้วย Ctrl + C — หยุดแค่การดู ไม่ได้หยุดงาน

รอบที่ปกติหน้าตาแบบนี้

2026-07-31 09:15:01 === lane=all bw=230m (total 230m / 1 lanes) conf=yes === 2026-07-31 09:15:02 R1: 'tank-hdd-nas' point-in-time ready 2026-07-31 09:15:04 [105] SYNC -> 8105 dest=ssd (used 9.8G, bw=230m, src=tank-hdd-nas) 2026-07-31 09:18:21 [105] OK -> 8105 (rc=0) 2026-07-31 09:18:22 === lane 'all' finished: ok=1 skipped=0 failed=0 ===

บรรทัดสุดท้ายคือบรรทัดที่ต้องดูทุกครั้ง

คำแปลว่า
okสำเร็จกี่ตัว
skippedข้ามกี่ตัว — ส่วนใหญ่คือสำเนากำลังถูกเปิดใช้อยู่ (วันฉุกเฉิน) ตั้งใจข้าม
failedล้มเหลวกี่ตัว — ถ้าไม่ใช่ 0 ต้องเปิด log ดู

หาปัญหาเร็วๆ

$ grep -E 'ERROR|GUARD|WARN' logs/$(ls -t logs | head -1)

ถ้าไม่มีอะไรขึ้นเลย แปลว่าไม่มีอะไรต้องห่วง

5

เพิ่ม CT ใหม่เข้าระบบ

  1. เปิด inventory-migrate.tsv เพิ่มหนึ่งบรรทัด — เลข CT กับชั้นเก็บ 
    $ nano inventory-replica.tsv
  2. รันมือหนึ่งรอบ ให้มัน copy ก้อนแรก (ตัวใหม่รอบแรกจะนาน) 
    $ ./ct-replica.sh --ctid 105
  3. เช็คว่าสำเนาเกิดแล้ว ต้องเห็นเลข 8xxx สถานะ stopped 
    $ ssh root@{backup_node} pct list

จบ หลังจากนี้ cron ดูแลต่อให้เอง

ซ้อม · วันฉุกเฉิน · กลับบ้าน

6

ซ้อม — เปิดสำเนาดูเฉยๆ (ปลอดภัย ทำได้ทุกเมื่อ)

สำเนาเกิดมาพร้อมเน็ตเหมือนตัวจริงทุกอย่าง แต่เสียบอยู่บนสวิตช์ปลอมที่ไม่มีสายออกนอกเครื่อง เปิดได้เลยแม้ตัวจริงกำลังทำงาน IP ซ้ำก็ไม่ชนกัน

$ ssh root@{backup_node}
$ pct start 8105
$ pct exec 8105 -- systemctl is-system-running    # did it finish booting?
$ pct shutdown 8105

ระหว่างสำเนาเปิดอยู่ โปรแกรมจะไม่เขียนทับ รอบ copy จะข้ามตัวนี้ให้เอง (ขึ้น skipped ใน log) แปลว่าสำเนาจะหยุดอัปเดตชั่วคราว — ซ้อมเสร็จรีบปิด อย่าทิ้งไว้ข้ามวัน

อยากยิงเข้าไปเทสจากข้างนอกด้วย (curl เว็บ ฯลฯ) ต้องเปิดขาชั่วคราวให้เครื่อง backup ใส่เลข VLAN กับ IP ให้ตรงกับ CT ตัวนั้น แล้วเก็บทิ้งเมื่อเสร็จ

$ ovs-vsctl add-port vmbr99 t50 -- set interface t50 type=internal -- set port t50 tag=50
$ ip addr add {free_ip_in_ct_subnet}/24 dev t50 && ip link set t50 up

$ curl http://{ct_ip}/

$ ip link set t50 down && ovs-vsctl del-port vmbr99 t50
7

ของจริง — เอาสำเนาขึ้นแทนตัวจริง

ใช้เมื่อตัวจริงพังหรือเครื่องเก็บข้อมูลล่มเท่านั้น

เช็คก่อนว่าตัวจริงดับสนิทจริงๆ ขั้นตอนนี้คือการย้ายสำเนาออกจากสวิตช์ปลอมมาสวิตช์จริง ซึ่งแปลว่าตั้งแต่วินาทีนั้น IP กับ MAC ของมันจะออกสายจริง ถ้าตัวจริงยังเปิดอยู่ = ชนกันทันที

  1. ยืนยันตัวจริงดับ 
    $ ssh root@{compute_node_xx} pct status 105    # must be stopped
  2. หยุดระบบสำเนาก่อน — ตั้งแต่ตอนนี้สำเนาคือข้อมูลตัวจริง ห้ามให้อะไรมาทับ 
    $ ssh root@{nfs_node} touch /root/tp/PAUSE
  3. ย้ายสำเนามาสวิตช์จริง เปลี่ยนคำเดียวคือ bridge — เลขและ IP ที่เหลือถูกอยู่แล้ว 
    $ ssh root@{backup_node}
$ grep ^net /etc/pve/nodes/{backup_node}/lxc/8105.conf   # read the current line first, then edit a copy of it
$ pct set 8105 -net0 {the same line, with bridge=vmbr99 changed to vmbr0}
  4. เปิดใช้งาน 
    $ pct start 8105
8

กลับบ้าน — ส่งข้อมูลคืนตัวจริง

มีโปรแกรมช่วยแล้ว ชื่อ ct-failback.sh อยู่โฟลเดอร์เดียวกัน มันเช็คทุกอย่างให้ก่อนเขียนทับ — อย่าใช้ rsync มือเอง

ลำดับสำคัญ: PAUSE ต้องมาก่อนปิดสำเนา ตัวกันไม่ให้เขียนทับทำงานเฉพาะตอนสำเนากำลังเปิด วินาทีที่ปิดสำเนา ระบบ copy รอบถัดไป (ทุก 15 นาที) จะเอาข้อมูลเก่าทับสำเนาทันที งานทั้งหมดช่วง DR หายเกลี้ยง — โปรแกรมจะไม่ยอมทำงานถ้าไม่มี PAUSE แต่รู้ไว้ว่าทำไม

ขั้นที่ 1 — ทยอยส่งกลับล่วงหน้า (ทำได้ตอนสำเนายังเปิดใช้งานอยู่)

รันซ้ำได้เรื่อยๆ ไม่กระทบคนใช้งาน แต่ละรอบส่งเฉพาะส่วนที่เปลี่ยน

$ ssh root@{nfs_node}
$ cd /root/tp
$ ./ct-failback.sh --list           # what state each CT is in
$ ./ct-failback.sh --all            # every CT (or --ctid 105 for one)

ดูเลข changed= ของแต่ละตัว รันซ้ำจนตัวเลขไม่ลดแล้ว = พร้อมตัดจริง

ขั้นที่ 2 — ตัดจริง

  1. หยุดระบบสำเนา 
    $ touch /root/tp/PAUSE
  2. ปิดสำเนาทุกตัวที่จะคืน 
    $ ssh root@{backup_node} pct shutdown 8105
  3. ส่งรอบสุดท้าย 
    $ ./ct-failback.sh --all --final

    ต้องจบด้วย failed=0 ถ้าไม่ใช่ ห้ามเปิดตัวจริง เรียกผู้ดูแลระบบ

  4. เปิดตัวจริง 
    $ ssh root@{compute_node_xx} pct start 105
  5. คืนสำเนากลับสวิตช์ปลอม — ข้อนี้ลืมไม่ได้ 
    $ ssh root@{backup_node}
$ pct set 8105 -net0 {the same line, with bridge=vmbr0 changed back to vmbr99}
$ grep ^net /etc/pve/nodes/{backup_node}/lxc/8105.conf   # every line must say vmbr99
  6. เปิดระบบสำเนากลับ 
    $ rm /root/tp/PAUSE
$ ./ct-replica.sh                   # the first round after this must end failed=0

โปรแกรมจะไม่ยอมทำงานถ้าอะไรไม่พร้อม เช่น CT ตัวจริงยังเปิดอยู่ (จะพังทันทีถ้าฝืน), สำเนายังไม่ปิดตอนสั่ง --final, หรือยังไม่ได้ PAUSE — มันจะบอกเป็นข้อๆ ว่าติดตรงไหน และตอน --final มันถ่ายภาพสำรองของ image เดิมไว้ให้ก่อนเขียนทับด้วย

ถ้าตัวไหนติดเงื่อนไข มันจะข้ามเฉพาะตัวนั้นแล้วทำตัวอื่นต่อ (ขึ้น skipped) แก้ตัวที่ติดแล้วรันซ้ำได้เลย

9

ข้อความที่เจอบ่อยใน log

ที่เห็นใน logแปลว่า / ต้องทำอะไร
OK ... (rc=0)
OK ... (rc=24)		 สำเร็จทั้งคู่ เลข 24 แปลว่ามีไฟล์เปลี่ยนระหว่าง copy ซึ่งปกติมากเพราะ CT จริงยังทำงานอยู่ ไม่ต้องทำอะไร
GUARD R2 ... RUNNING สำเนาตัวนั้นกำลังถูกเปิดใช้อยู่ (โหมดฉุกเฉิน) โปรแกรมเลยไม่เขียนทับ ตั้งใจให้เป็นแบบนี้ — แต่ถ้าไม่มีใครเปิดโหมดฉุกเฉินอยู่ แปลว่ามีคนลืมปิดสำเนา ไปปิดตามข้อ 7
rc=23
IO error encountered		 อ่านบางไฟล์ไม่ได้เพราะตอนถ่ายภาพ CT กำลังเขียนอยู่พอดี รอบเดียวถือว่าปกติ รอบถัดไปถ่ายภาพใหม่แล้วมักได้ครบ (โปรแกรมจะไม่สร้างสำเนาที่ข้อมูลไม่ครบให้ใช้เด็ดขาด) · ถ้าขึ้น TWICE IN A ROW = ไม่ปกติแล้ว เรียกผู้ดูแลระบบ
inventory is broken - NOTHING was run ไฟล์รายชื่อมีบรรทัดผิด (ซ้ำ/พิมพ์ผิด) โปรแกรมบอกเลขบรรทัดให้ รอบนี้ยังไม่ได้ทำอะไรเลย แก้แล้วรันใหม่
WARN R11 ...
NOT on vmbr99		 มีสำเนาที่เคยเอาขึ้นใช้จริงแล้วยังไม่ได้ย้ายกลับสวิตช์ปลอม ตอนนี้มันถือ IP จริงอยู่ ใครกดเปิดก็ชนทันที — ทำข้อ 5 ของหัวข้อ "กลับบ้าน" ให้จบ
PAUSED by ... มีคนสั่งหยุดระบบสำเนาไว้ (ไฟล์ PAUSE) ปกติใช้ตอนส่งข้อมูลกลับ ถ้างานนั้นจบแล้วต้องลบไฟล์ทิ้ง ไม่งั้นสำเนาไม่อัปเดตเลย
GUARD R8 ... มีคนเปลี่ยนชั้น ssd↔hdd ของตัวที่มีสำเนาแล้ว โปรแกรมหยุดไว้กันข้อมูลแตกเป็นสองที่ อย่าฝืน เรียกผู้ดูแลระบบ
no CT matched --storage ... พิมพ์ชื่อ storage ผิด หรือไม่มี CT ตัวไหนอยู่บนนั้น เช็คตัวสะกดในคำสั่ง
NOT MOUNTED / GUARD R1 / GUARD R3 ที่เก็บข้อมูลฝั่งใดฝั่งหนึ่งหายไป โปรแกรมหยุดเองก่อนของจะพัง อย่าฝืนรันซ้ำ เรียกผู้ดูแลระบบทันที

หลักง่ายๆ คำว่า NOTE กับ skip คือเรื่องปกติ ปล่อยได้ ส่วน ERROR GUARD WARN คือต้องอ่านก่อนไปต่อ และบรรทัดสรุปท้ายรอบต้องได้ failed=0 เสมอ

งานนานๆ ให้รันใน tmux

ใช้ตอนเพิ่ม CT ใหม่ตัวใหญ่ๆ ที่รอบแรกกินเวลาเป็นชั่วโมง จะได้ปิดคอมกลับบ้านได้

  1. เปิดหน้าจอค้างไว้ในเครื่อง 
    $ tmux new -s rep
  2. สั่งงานตามปกติ 
    $ cd /root/tp && ./ct-replica.sh --ctid 105
  3. ถอยออกมาโดยงานยังรัน กด Ctrl ค้างแล้วกด b ปล่อยมือทั้งคู่ แล้วกด d

กลับมาดูเมื่อไหร่ก็ tmux attach -t rep · ลืมชื่อ ใช้ tmux ls

คู่มือนี้เป็นฉบับใช้งานประจำวัน · การติดตั้งครั้งแรกอยู่ใน ct-replica-setup.html
