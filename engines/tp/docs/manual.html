คู่มือใช้งาน ct-migrate

ย้าย CT จากเครื่องเก่าไปเครื่องใหม่ — ฉบับใช้งานจริง อ่านรอบเดียวทำได้เลย

ทุกคำสั่งในคู่มือนี้พิมพ์บนเครื่อง storage-node เท่านั้น
0

เริ่มต้น

ล็อกอินเข้าเครื่อง storage-node แล้วเข้าไปที่โฟลเดอร์ที่เก็บโปรแกรมไว้

$ ssh root@pve-r740xd
$ cd ~/ct-migrate
$ ls

ถ้ามาถูกที่ จะเห็นประมาณนี้

ct-migrate.sh ctmig.conf inventory-migrate.tsv done logs state

ถ้าไม่เห็น ct-migrate.sh แปลว่ายังไม่ได้อยู่ในโฟลเดอร์ที่ถูกต้อง อย่าเพิ่งพิมพ์คำสั่งอื่น

โปรแกรมนี้ปลอดภัยกับ CT ตัวเก่า ระหว่าง copy CT เก่ายังทำงานตามปกติ ไม่ดับ ไม่ถูกแตะต้อง และตัวโปรแกรมไม่เคยสั่งเปิดหรือปิด CT ใดๆ เอง ทุกอย่างที่เป็นการเปิด-ปิดเราทำเองด้วยมือ

ส่วนที่ 1

ใช้งานตัวโปรแกรม

1

ไฟล์ที่ต้องรู้จัก มี 3 ไฟล์

ไฟล์คืออะไรต้องแก้ไหม
ct-migrate.shตัวโปรแกรมไม่ต้องแก้เด็ดขาด
inventory-migrate.tsvรายชื่อ CT ที่จะย้ายแก้บ่อยที่สุด
ctmig.confตั้งค่าความเร็วตั้งครั้งเดียวจบ

ส่วนโฟลเดอร์ logs state done โปรแกรมสร้างเอง ไม่ต้องไปยุ่ง ยกเว้น done ที่เราจะใช้ตอนปิดงาน (ข้อ 6)

2

inventory-migrate.tsv — บอกว่าจะย้ายตัวไหน

หนึ่งบรรทัด = CT หนึ่งตัว มี 5 ช่อง เรียงตามลำดับนี้เสมอ

10.100.1.11   100   251   10.100.1.31   tank-hdd-nas
10.100.1.12   100   253   10.100.1.32   tank-ssd-nas
ช่องความหมายตัวอย่าง
1ไอพีเครื่องเก่า10.100.1.11
2เลข CT บนเครื่องเก่า100
3เลข CT ที่จะใช้บนเครื่องใหม่251
4ไอพีเครื่องใหม่10.100.1.31
5ชื่อ storagetank-hdd-nas

กฎ 3 ข้อ

  • ต้องครบ 5 ช่องทุกบรรทัด ขาดช่องไหนก็ตาม บรรทัดนั้นจะถูกข้ามและขึ้น ERROR ใน log
  • เลขช่องที่ 3 ห้ามซ้ำกันเด็ดขาด ถ้าซ้ำ โปรแกรมจะไม่ยอมทำอะไรเลยทั้งไฟล์ แล้วบอกว่าซ้ำที่บรรทัดไหน
  • เลขช่องที่ 2 ซ้ำได้ ถ้าอยู่คนละเครื่อง เป็นเรื่องปกติ เพราะแต่ละเครื่องเก่าเริ่มนับที่ 100 เหมือนกันหมด

วิธีเพิ่มบรรทัดที่พลาดยากที่สุด คือ copy บรรทัดเดิมทั้งบรรทัด วางต่อท้าย แล้วแก้เฉพาะตัวเลข จะได้ไม่มีช่องไหนหาย ระหว่างช่องจะเคาะ space หรือกด Tab ก็ได้ ขอแค่มีช่องว่างคั่น

บรรทัดที่ขึ้นต้นด้วย # คือคำอธิบาย โปรแกรมจะข้ามให้ ใช้พักบรรทัดที่ยังไม่อยากให้ทำงานได้

3

ctmig.conf — ตั้งความเร็ว

ทั้งไฟล์มีให้ปรับจริงๆ แค่ 2 บรรทัดนี้

BW_TOTAL_MB=500
LANES=1
  • BW_TOTAL_MB คือความเร็วรวมสูงสุด หน่วยเป็น MB ต่อวินาที ตั้งไว้ 500 ตั้งสูงกว่านี้ไม่ได้ช่วย เพราะดิสก์ฝั่งเครื่องเก่าวิ่งได้ประมาณนี้
  • LANES คือจะให้รันพร้อมกันได้กี่สาย ถ้ารันทีละคำสั่งอยู่แล้วให้เป็น 1 ความเร็วข้างบนจะถูกหารตามจำนวนสาย

แก้แล้วมีผลกับรอบถัดไปทันที ไม่ต้องรีสตาร์ทอะไรทั้งนั้น

4

คำสั่งที่ใช้จริง มี 4 แบบ

$ ./ct-migrate.sh
$ ./ct-migrate.sh --storage tank-ssd-nas
$ ./ct-migrate.sh --ctid 251
$ ./ct-migrate.sh --ctid 251 --stopped
คำสั่งทำอะไร
./ct-migrate.shทำทุกบรรทัดใน inventory-migrate.tsv
--storage ...ทำเฉพาะ CT ที่อยู่บน storage นั้น
--ctid 251ทำเฉพาะ CT ตัวเดียว (ใส่เลขช่องที่ 3)
--ctid 251 --stoppedรอบสุดท้าย ใช้ตอน CT เก่าถูกปิดแล้วเท่านั้น

รันซ้ำได้เรื่อยๆ ไม่มีอันตราย แต่ละรอบจะ copy เฉพาะส่วนที่เปลี่ยนไป รอบแรกนานที่สุด รอบต่อๆ ไปจะเร็วขึ้นมากและข้อมูลที่ต้อง copy จะน้อยลงเรื่อยๆ นั่นคือสัญญาณว่าใกล้ย้ายได้แล้ว

5

ดู log

log อยู่ในโฟลเดอร์ logs แยกเป็นไฟล์ต่อวัน

ดูสดๆ ขณะกำลังรัน

$ tail -f logs/ctmig-all-$(date +%F).log

ออกจากหน้านี้ด้วย Ctrl + C — เป็นการหยุดแค่การดู log ไม่ได้หยุดงานที่กำลังรัน

ชื่อไฟล์ log เปลี่ยนไปตามคำสั่งที่รัน เช่นใส่ --storage tank-ssd-nas ชื่อไฟล์จะกลายเป็น ctmig-tank-ssd-nas-... และรอบสุดท้ายที่ใส่ --stopped จะได้ ctmig-all-final-... ถ้าจำไม่ได้ว่าไฟล์ไหน ใช้คำสั่งนี้เปิดไฟล์ล่าสุดได้เลย

$ tail -f logs/$(ls -t logs | head -1)

ดูย้อนหลัง

$ ls -lt logs/ | head
$ tail -40 logs/ctmig-all-2026-07-31.log

รอบที่ปกติจะหน้าตาแบบนี้

2026-07-31 02:00:01 lane=all bw=500m (total 500m / 1 lanes) conf=yes 2026-07-31 02:00:02 [251] size: quota=20G used=10G x185% -> alloc 20G 2026-07-31 02:00:02 [251] alloc 20G on 'tank-hdd-nas' + mkfs.ext4 2026-07-31 02:00:03 [251] rsync <= root@10.100.1.11:/proc/3417/root/ bw=500m 2026-07-31 02:41:55 [251] rootfs synced (rsync rc=0) 2026-07-31 02:41:56 [251] create CT config on 10.100.1.31 (no net, onboot=0, stopped) 2026-07-31 02:41:56 lane 'all' finished: ok=1 skipped=0 frozen=0 failed=0

บรรทัดสุดท้ายคือบรรทัดที่ต้องดูทุกครั้ง อ่านง่ายๆ ดังนี้

คำแปลว่า
okสำเร็จกี่ตัว
skippedข้ามไปกี่ตัว — ปกติ ไม่ใช่ปัญหา รอบหน้าจะทำให้เอง
frozenปิดงานไปแล้วกี่ตัว (ตัวที่มีไฟล์ใน done)
failedล้มเหลวกี่ตัว — ถ้าไม่ใช่ 0 ต้องเปิด log ดู

หาปัญหาเร็วๆ

$ grep -E 'ERROR|GUARD|WARN' logs/ctmig-all-2026-07-31.log

ถ้าไม่มีอะไรขึ้นเลย แปลว่าไม่มีอะไรต้องห่วง

6

ปิดงาน CT ด้วย done

เมื่อย้าย CT ตัวไหนเสร็จสมบูรณ์และเปิดใช้งานบนเครื่องใหม่แล้ว ให้บอกโปรแกรมว่าเลิกยุ่งกับตัวนี้ได้แล้ว

$ touch done/251.done

ตัวเลขคือเลข CT ใหม่ (ช่องที่ 3) หลังจากนี้ทุกรอบจะข้าม CT ตัวนี้ถาวร และไปโผล่ที่ช่อง frozen ในบรรทัดสรุปแทน

ข้อนี้สำคัญ ต้องทำหลังย้ายเสร็จเสมอ ถ้าลืม รอบถัดไปโปรแกรมจะ copy ทับ CT ตัวใหม่ที่กำลังใช้งานอยู่ (ถ้า CT ใหม่เปิดอยู่จะมีตัวกันไว้อีกชั้น แต่อย่าไปเสี่ยง)

ถ้าเผลอ touch ผิดตัว ลบไฟล์นั้นทิ้งได้ตามปกติ

$ ls done/
$ rm done/251.done
7

ลำดับตอนย้ายจริง

ห้ามสลับลำดับ โดยเฉพาะข้อ 2 กับ 3

  1. รันรอบธรรมดาไปเรื่อยๆ จนข้อมูลที่ copy แต่ละรอบเหลือน้อย 
    $ ./ct-migrate.sh --ctid 251
  2. ปิด CT ตัวเก่าด้วยมือ ที่เครื่องเก่า แล้วรอจนดับสนิทจริงๆ 
    $ ssh root@10.100.1.11 pct shutdown 100
$ ssh root@10.100.1.11 pct status 100
  3. รอบสุดท้าย เก็บข้อมูลช่วงท้ายที่ยังไม่ได้ copy 
    $ ./ct-migrate.sh --ctid 251 --stopped
  4. ปิดงาน 
    $ touch done/251.done
  5. เพิ่ม net0 ให้ CT ใหม่ แล้วค่อยเปิดเครื่อง ตัวเลขและไอพีข้างล่างเป็นแค่ตัวอย่าง ให้แก้ให้ตรงกับของจริง 
    $ ssh root@10.100.1.31 pct set 251 -net0 name=eth0,bridge=vmbr0,ip=10.100.1.51/24,gw=10.100.1.1
$ ssh root@10.100.1.31 pct start 251

ทำไมต้องปิดเครื่องเก่าก่อนแล้วค่อยรอบสุดท้าย เพราะตราบใดที่ CT เก่ายังทำงานอยู่ ข้อมูลมันก็ยังเปลี่ยนตลอดเวลา รอบสุดท้ายจึงต้องทำตอนมันหยุดนิ่งแล้วเท่านั้น ข้อมูลถึงจะครบจริง

CT ใหม่จะไม่มีเน็ตจนกว่าเราจะใส่เอง ตั้งใจให้เป็นแบบนั้น กันไม่ให้เครื่องเก่ากับเครื่องใหม่ออกเน็ตด้วยไอพีเดียวกันพร้อมกัน ดังนั้นอย่าเพิ่งเปิด CT ใหม่ก่อนที่จะแน่ใจว่าเครื่องเก่าดับแล้ว

ส่วนที่ 2

รันทิ้งไว้ด้วย tmux

8

ทำไมต้องใช้

การ copy ใช้เวลาเป็นชั่วโมง ถ้ารันตรงๆ แล้วปิดหน้าต่าง หรือเน็ตหลุด งานจะตายกลางคัน

tmux คือการเปิดหน้าจอทิ้งไว้ในเครื่อง งานจะรันต่อในเครื่องแม้เราจะปิดคอมกลับบ้านไปแล้ว พรุ่งนี้ค่อยกลับมาเปิดดูต่อได้

9

ใช้จริง 3 ขั้น

  1. เปิดหน้าจอใหม่ ตั้งชื่อว่า mig 
    $ tmux new -s mig
  2. สั่งงานตามปกติ 
    $ cd ~/ct-migrate
$ ./ct-migrate.sh
  3. ถอยออกมา โดยงานยังรันอยู่ กด Ctrl + b แล้วปล่อยมือ จากนั้นค่อยกด d

ตอนนี้ปิด terminal ได้เลย งานยังวิ่งอยู่ในเครื่อง อยากกลับเข้าไปดูเมื่อไหร่ก็

$ tmux attach -t mig

วิธีกด Ctrl+b d ไม่ได้กดสามปุ่มพร้อมกัน ให้กด Ctrl ค้างแล้วกด b ปล่อยมือทั้งคู่ แล้วค่อยกด d ตัวเดียว

10

คำสั่ง tmux เท่าที่ต้องใช้

คำสั่งทำอะไร
tmux new -s migเปิดหน้าจอใหม่ ชื่อ mig
tmux lsดูว่าตอนนี้มีหน้าจอค้างอยู่กี่อัน ชื่ออะไรบ้าง
tmux attach -t migกลับเข้าไปที่หน้าจอชื่อ mig
tmux attachกลับเข้าอันล่าสุด ใช้ได้เมื่อมีอันเดียว
กด Ctrl+b แล้ว dถอยออกมา งานยังรันต่อ
exitปิดหน้าจอทิ้ง ใช้เมื่องานจบแล้วจริงๆ
tmux kill-session -t migสั่งฆ่าหน้าจอนั้นทิ้งจากข้างนอก

kill-session คือการฆ่างานที่กำลังรันด้วย ข้อมูลที่ copy ไปแล้วไม่หาย รอบหน้ารันต่อจากจุดเดิมได้ แต่ถ้าไม่จำเป็นก็ไม่ต้องใช้ — ใช้ exit ตอนงานจบแล้วก็พอ

ถ้าลืมว่าตั้งชื่ออะไรไว้ พิมพ์ tmux ls มันจะบอกชื่อทั้งหมด แล้วค่อยเอาชื่อนั้นไปต่อท้าย tmux attach -t

ส่วนที่ 3

เจอแบบนี้ทำยังไง

11

ข้อความที่เจอบ่อยใน log

ที่เห็นใน logแปลว่า / ต้องทำอะไร
rsync rc=0
rsync rc=24		 สำเร็จทั้งคู่ เลข 24 แปลว่ามีไฟล์บางไฟล์หายไประหว่าง copy ซึ่งเป็นเรื่องปกติมากเพราะ CT เก่ายังทำงานอยู่ ไม่ต้องทำอะไร
is busy in another lane - skip เครื่องเก่าตัวนั้นกำลังถูกใช้อยู่ในอีกสายหนึ่ง เลยข้ามไปก่อน ปกติ รอบหน้าจะทำให้เอง
names the same CT more than once มี CT ซ้ำใน inventory-migrate.tsv โปรแกรมบอกเลขบรรทัดให้ด้วย รอบนี้ยังไม่ได้ทำอะไรเลยสักตัว แก้บรรทัดที่ซ้ำแล้วรันใหม่
row is incomplete บรรทัดนั้นใส่ไม่ครบ 5 ช่อง บรรทัดอื่นยังทำงานปกติ กลับไปแก้บรรทัดนั้น
extra mountpoint(s) สำคัญ CT เก่ามีดิสก์ก้อนอื่นแปะอยู่ และข้อมูลในนั้นไม่ได้ถูก copy มาด้วย log จะบอกชื่อ path ให้ครบทุกอัน ต้อง copy เองก่อนเปิดใช้งานจริง ไม่งั้น CT ใหม่จะเปิดติดแต่โฟลเดอร์นั้นว่างเปล่า
GUARD ... โปรแกรมเจอสถานการณ์ที่ถ้าทำต่อของจะพัง เลยหยุดไว้เอง อย่าฝืนรันซ้ำ เอา log ไปให้คนดูแลระบบดู
still out of space พื้นที่ไม่พอ โปรแกรมขยายให้เองแล้ว 3 ครั้งแต่ยังไม่พอ ต้องให้คนดูแลระบบเข้ามาดู

หลักง่ายๆ คำว่า NOTE กับ skip คือเรื่องปกติ ปล่อยได้ ส่วน ERROR GUARD WARN คือต้องอ่านก่อนไปต่อ และบรรทัดสรุปท้ายรอบต้องได้ failed=0 เสมอ
