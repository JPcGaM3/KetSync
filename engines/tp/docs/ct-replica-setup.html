ติดตั้ง ct-replica

ทำครั้งเดียวจบ — หลังจากนั้นใช้งานตามคู่มือใช้งาน (อีกไฟล์หนึ่ง)

ทำตามลำดับ 1 → 5 ห้ามข้าม
0

ระบบนี้มี 3 เครื่อง

เครื่องหน้าที่
{compute_node_xx}เครื่องที่ CT ของลูกค้าทำงานอยู่จริง
{nfs_node}เครื่องเก็บข้อมูลของ CT ทั้งหมด — ตัวโปรแกรมติดตั้งที่นี่
{backup_node}เครื่องเก็บสำเนา — สำเนาทุกตัวถูกปิดไว้ รอวันฉุกเฉิน

โปรแกรมจะ copy ข้อมูล CT จาก {nfs_node} ไปเก็บเป็นสำเนาบน {backup_node} โดยแบ่งเป็น 2 ชั้น: ssd สำหรับ CT ที่ต้องกู้คืนไว และ hdd สำหรับ CT ทั่วไป

1

เตรียมเครื่อง backup

ล็อกอินเข้า {backup_node} แล้วรันสคริปต์เตรียมเครื่อง (แค่ครั้งเดียว)

$ ssh root@{backup_node}
$ bash bkp02-setup.sh

สคริปต์จะสร้างพื้นที่เก็บสำเนา ตั้งค่าทุกอย่างให้ และพิมพ์คำสั่งตรวจสอบให้ที่ท้ายจอ รันซ้ำได้ ไม่มีอันตราย

ถ้าขึ้น ERROR ว่า pool ไม่มี แปลว่าเครื่องนี้ยังไม่ได้สร้าง pool replica-hdd / replica-ssd — ต้องให้ผู้ดูแลระบบสร้างก่อน แล้วค่อยรันสคริปต์นี้ใหม่

2

เตรียมเครื่อง nfs

ล็อกอินเข้า {nfs_node} วางไฟล์โปรแกรม แล้วผูกกุญแจ ssh ไปหาเครื่อง backup

  1. เอา repo ลงเครื่อง ทุกอย่างอยู่ในโฟลเดอร์เดียว แนะนำ /root/tp 
    $ mkdir -p /root/tp
$ cd /root/tp
$ ls
    ct-replica.sh ctrep.conf inventory-migrate.tsv.sample
  2. ทำให้โปรแกรมรันได้ 
    $ chmod +x ct-replica.sh
  3. ผูกกุญแจ ssh ให้เครื่องนี้เข้าเครื่อง backup ได้โดยไม่ถามรหัสผ่าน (ครั้งเดียว) 
    $ ssh-copy-id root@{backup_node}
$ ssh root@{backup_node} hostname

    บรรทัดที่สองต้องพิมพ์ชื่อเครื่อง backup ออกมาโดยไม่ถามรหัสผ่าน ถึงจะผ่าน

3

สร้างรายชื่อ CT ที่จะทำสำเนา

copy ไฟล์ตัวอย่างมาเป็นไฟล์จริง แล้วใส่รายชื่อของเรา

$ cp inventory-replica.sample.tsv inventory-replica.tsv
$ nano inventory-replica.tsv

หนึ่งบรรทัด = CT หนึ่งตัว ใส่แค่เลข CT กับชั้นเก็บก็พอ

105   ssd     # important customer -> fast tier
112   hdd     # ordinary tier
113           # no tier named = ordinary tier

เลขสำเนาไม่ต้องคิดเอง โปรแกรมตั้งให้อัตโนมัติ (เลขเดิม + 8000 เช่น 105 → 8105) รายละเอียดช่องอื่นๆ อยู่ในคู่มือใช้งาน

4

รันครั้งแรกด้วยมือ

รอบแรกจะช้าที่สุดเพราะ copy ทั้งก้อน รอบต่อไปเร็วขึ้นมาก

$ cd /root/tp
$ ./ct-replica.sh

รอจนจบ แล้วดูบรรทัดสุดท้าย ต้องได้แบบนี้

=== lane 'all' finished: ok=3 skipped=0 failed=0 ===

failed ต้องเป็น 0 ถ้าไม่ใช่ ให้เปิด log ดูตามวิธีในคู่มือใช้งาน แก้ให้ผ่านก่อน แล้วค่อยไปข้อ 5 — อย่าตั้งเวลาอัตโนมัติทั้งที่ยังรันมือไม่ผ่าน

5

ตั้งให้รันเองทุก 15 นาที

แยกเป็น 2 สายตามที่เก็บข้อมูลต้นทาง จะได้ไม่รอคิวกัน

$ echo '*/15 * * * * root /root/tp/ct-replica.sh --storage tank-hdd-nas >/dev/null 2>&1' > /etc/cron.d/ct-replica-hdd
$ echo '*/15 * * * * root /root/tp/ct-replica.sh --storage tank-ssd-nas >/dev/null 2>&1' > /etc/cron.d/ct-replica-ssd

แล้วเปิดไฟล์ ctrep.conf แก้หนึ่งบรรทัด บอกโปรแกรมว่ามี 2 สายวิ่งพร้อมกัน (โปรแกรมจะแบ่งความเร็วให้เอง)

LANES=2

เสร็จแล้ว รอ 15 นาทีแล้วเช็คว่ามันทำงานเองจริง

$ tail -5 logs/$(ls -t logs | head -1)
6

เช็คก่อนปิดจ๊อบ

  • รันมือผ่าน failed=0 อย่างน้อย 1 รอบ
  • ไฟล์ cron 2 ไฟล์อยู่ใน /etc/cron.d/ และ LANES=2
  • บนเครื่อง backup เห็นสำเนา: ssh root@{backup_node} pct list — ทุกตัวต้องเป็นเลข 8xxx และสถานะ stopped

เสร็จแล้ว จากนี้ไปใช้งานประจำวันตามคู่มือใช้งาน ไม่ต้องกลับมาแตะไฟล์ติดตั้งอีก
