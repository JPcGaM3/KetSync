01 — ระบบนี้คืออะไร

ห้านาที — เครื่อง 4 ตัว สองชั้น เลข 3 ชุด และกติกาเหล็ก 3 ข้อ

อ่านหน้านี้ก่อนหน้าอื่นทั้งหมด ไม่มีคำสั่งต้องพิมพ์
1

เครื่อง 4 ตัว

เครื่องIPหน้าที่
storage10.100.1.17 เก็บไฟล์ดิสก์จริงของทุก CT และเป็นที่ที่ engine ทุกตัวรัน — ตัวหลัก (master)
backup10.100.1.9 เก็บสำเนา DR ที่ปิดอยู่ + PBS และเป็นเครื่องที่ใช้สั่งงานวันที่ storage ตาย
compute10.100.1.32 / .33 รัน CT โดย mount ดิสก์จาก storage ผ่าน NFS ไม่ต้องติดตั้งอะไรเพิ่ม

เครื่อง storage อยู่นอก cluster โดยตั้งใจ — ถ้ามันร่วมโหวตด้วยแล้วล่ม cluster จะเสียเสียงโหวตไปพร้อมกับดิสก์ ทุกช่องที่คนกรอกในระบบนี้จึงเป็น IP ไม่มี hostname

2

สองชั้น — ตัดสินใจ กับ ลงมือ

ชั้นอยู่ที่ทำอะไร
ketsyncbin/ + lib/ ตัดสินใจ — ใครเป็นตัวหลัก, CT ไหนอยู่ไหน, ลำดับขั้นตอน, เมลเตือน
enginesengines/ ลงมือขน — ย้าย/ก๊อป/เอากลับตัว rootfs จริง พร้อม guard ทุกด่าน

สั่งทุกอย่างผ่าน ./ketsync ตัวเดียว ของที่แตะข้อมูลลูกค้าอยู่ฝั่ง engines ทั้งหมด

คำสั่งทำอะไรสั่งจาก
replicaดิสก์จริง → สำเนาปิดบนเครื่อง backup (cron ทุก 15 นาที)storage
distributeสำเนา → ดิสก์ในตัวเครื่อง compute (9xxx) — วัน storage ตายbackup
recall9xxx → กลับเข้าสำเนาbackup
failbackสำเนา → กลับเข้าดิสก์จริงstorage
recoverทางกลับทั้งสายในคำสั่งเดียว อ่านจากบันทึกจริงว่าเหลืออะไรstorage
migrateCT จากเครื่องเก่านอกฟลีต → ดิสก์บน storagestorage
watchเฝ้าฟลีตจาก cron แล้วเมลเมื่อมีอะไรเปลี่ยนstorage
doctorตรวจทุกอย่างที่ไม่มีใครจำได้ว่าต้องตรวจ อ่านอย่างเดียวที่ไหนก็ได้
syncส่งตาราง 4 ไฟล์ไปทุกเครื่องที่มี ketsyncmaster
3

เลข 3 ชุด ที่ไม่มีใครต้องพิมพ์เอง

เลขคืออะไรอยู่ที่ไหน
300ตัวจริงดิสก์บนเครื่อง storage ผ่าน NFS
8300สำเนา DR ปิดอยู่เสมอ ก๊อปทุก 15 นาทีเครื่อง backup
9300ตัวชั่วคราวตอนฉุกเฉินดิสก์ในตัวเครื่อง compute

ทุกคำสั่งรับเลขตัวจริงตัวเดียว ที่เหลือระบบคิดเองจาก OFFSET สองตัวใน conf เห็นเลข 9 นำหน้าใน pct list เมื่อไหร่ = ของชั่วคราวที่ต้องมีคนเก็บ

4

กติกาเหล็ก 3 ข้อ

  • ไม่มีคำสั่งไหนเปิดหรือปิด container ให้ ทุกตัวย้ายข้อมูล เขียน config แล้วพิมพ์ pct start ออกมาให้คนกดเอง — จังหวะที่บริการลูกค้ากลับมา ต้องมีคนนั่งดูหน้าจออยู่
  • ปฏิเสธเสียงดัง ดีกว่าทำต่อเงียบๆ เจอ GUARD ไม่ได้แปลว่าพัง แปลว่ามันกันไว้ให้แล้ว พร้อมบอกว่าทำไมและต้องทำอะไรต่อ ไม่มี --force ให้ใช้
  • ไม่มีค่า default ไม่มีการเดา แถวที่ลืมกรอกหน้าตาเหมือนแถวที่ตั้งใจทุกอย่าง ระบบจึงปฏิเสธทั้งไฟล์พร้อมบอกเลขบรรทัด แทนที่จะเดาแล้วเอาสำเนาลูกค้าไปวางที่ที่ไม่มีใครเลือก

อยากเห็นภาพทั้งระบบละเอียดกว่านี้ อ่าน how-it-works.html (ไม่มีคำสั่ง อ่านตอนว่าง) อยากรู้เหตุผลเบื้องหลัง อ่าน ../decisions.md
