06 — อ้างอิง

เปิดค้น ไม่ต้องอ่านเรียง — รหัสออก flag ทุก guard บรรทัดเดียว คีย์ conf และไฟล์ทุกไฟล์

ทุกคำปฏิเสธในระบบพิมพ์เหตุผลของมันเองใน log เสมอ หน้านี้คือฉบับเปิดหาเร็ว

3

ทุก guard บรรทัดเดียว

เจอ GUARD ใน log = ระบบกันไว้ให้แล้ว พร้อมเหตุผลใต้บรรทัดนั้นเสมอ ตารางนี้ไว้เปิดหาความหมายเร็วๆ ฉบับเต็มพร้อมเหตุผลอยู่ใน CLAUDE.md กับ ../decisions.md

migrate — G

G1pool ต้องไม่อยู่บนดิสก์ระบบ และต้อง mount อยู่จริง — เช็กก่อนจองเนื้อที่
G2ไม่ก๊อปทับ CT ที่กำลังรันบนเครื่องปลายทาง
G3ต้อง unmount ก่อน resize เสมอ
G4เนื้อที่หมด = ขยาย image 5% แล้วลองใหม่ สามครั้งแล้วบอกตรงๆ
G5เขียน config ต่อเมื่อก๊อปจบดี (rc 0/24) เท่านั้น
G6config ที่มีอยู่แล้วไม่ถูกเขียนทับ แค่รายงาน
G7เลขปลายทางต้องว่างจริงทั้ง cluster
G8net จากต้นทางถูกวางบน vmbr99 ของเครื่องปลายทาง — bridge นั้นต้องมีจริงและไม่มีทางออก เช็กก่อนก๊อป และ net ที่ไม่มี bridge= = ปฏิเสธ ไม่ตัดทิ้งเงียบๆ (go-live = สลับ bridge กลับ)

replica — R

R1อ่านจาก snapshot+clone เสมอ ไม่อ่าน image ที่กำลังถูกเขียน
R2ไม่ก๊อปทับสำเนาที่กำลังรัน (แปลว่ามีคน promote ไปแล้ว)
R3dataset ปลายทางต้อง mounted=yes
R4เลขปลายทางต้องไม่เป็นของ guest อื่นที่ไหนเลยใน cluster — เช็กก่อนก๊อป
R5เขียน config หลังก๊อปจบดี แล้วอ่านกลับมาเทียบ
R6loop-mount แบบ ro,noload — ไม่มีการเขียนลง clone
R7 / R10lock ราย lane และรายสำเนา — สองรอบไม่ทับกัน
R8config สำเนาที่มีอยู่ต้องตรงกับ dest ในใบงาน
R9bridge เก็บสำเนา (vmbr99) ต้องไม่มีทางออกเน็ตจริงๆ — ถาม OVS แบบ ifaces ด้วย
R11เตือนเมื่อสำเนาที่ปิดอยู่ค้างบน bridge จริง
R12storage ต้นทางตายทั้งก้อน = ข้อเท็จจริงเดียว ข้ามพร้อมบอกครั้งเดียว และรอบนั้นไม่เขียว
R13มี 9xxx อยู่ = ข้อมูลใหม่สุดอยู่ที่อื่น สำเนาถูกปล่อยไว้จนกว่าใครจะ destroy 9xxx
R14lock สำเนาที่เครื่องที่ถือมัน — kernel ปลายทางเป็นกรรมการ ใช้ร่วมกับ B8/D8/C8
R15สำเนาที่ PVE ล็อกอยู่เอง (เช่น lock: backup ตอน PBS กำลัง backup) = ข้าม ตัวสำเนาไม่พัง รอบหน้าซ่อมให้อยู่แล้ว ที่พังคือ ไฟล์ backup ซึ่งจะได้ครึ่งรอบเก่าครึ่งรอบใหม่ นับเป็น skip ไม่ใช่ error หายเองเมื่องานนั้นจบ — และทำงานกลับทิศด้วย: ระหว่างรอบกำลังเขียน สำเนาจะถือ lock: disk ไว้ ถ้าตาราง backup ของ PVE ยิงมากลางรอบ vzdump จะปฏิเสธตัวนั้นเสียงดังใน job log แทนที่จะได้ backup เน่าเงียบๆ แล้วปลดล็อกทันทีที่รอบจบ ไม่ว่าจบดีหรือพัง ถ้ารอบตายกลางทางจนล็อกค้าง รอบถัดไปจะบอกเอง พร้อมคำสั่ง pct unlock ที่ใช้เคลียร์

สองอย่างที่ replica ทำเพิ่ม ไม่ใช่ guard แต่อยู่ตรงนี้ให้หาง่าย:

snapshot รายวันรอบไหนเขียว สำเนาบนเครื่อง backup จะถูก snapshot วันละครั้ง ชื่อ ketsync-<วันที่> เก็บไว้ SNAP_KEEP วัน ได้สามอย่างจากคำสั่งเดียว: จุดย้อนกลับเมื่อรอบใดรอบหนึ่งตายกลางคัน, ประวัติ (replica ทำให้สำเนา เหมือน ตัวจริง ลบอะไรก็ลบตาม — snapshot คือเส้นแบ่งระหว่างสำเนากับ backup), และเปิดดูไฟล์ย้อนหลังได้ที่ .zfs/snapshot/ ตรงๆ
--move-destคำตอบของ R8 ย้ายสำเนาข้าม pool ด้วยคำสั่งเดียว ลำดับคือทั้งหมดของเรื่อง: ก๊อปก่อน (พา snapshot ไปด้วย) → ตรวจ → แก้ config ให้ชี้ที่ใหม่แล้วอ่านกลับมาเทียบ → ค่อยลบของเก่าเป็นขั้นสุดท้าย ทุกขั้นก่อนหน้านั้นพังได้ ของเก่ายังบูตได้อยู่

failback — B

B1ตัวจริงต้องปิดสนิท — ติดต่อไม่ได้ไม่นับว่าปิด
B2presync: สำเนารันอยู่ หรือปิดแต่มี 9xxx / --final: สำเนาปิด + มี PAUSE
B3 / B4 / B5image ต้องอยู่บน mount จริง ต้องมีอยู่แล้ว และ unmount ก่อน resize
B6เนื้อที่หมด = ขยาย image แทนที่จะทิ้งงานกลางทาง
B7--final ต้อง snapshot กันพลาดได้ก่อน ไม่งั้นปฏิเสธ (--no-snapshot คือทางผ่านที่ต้องพิมพ์เอง)
B8R14 ฝั่ง failback

distribute — D

D1ตัวจริงต้องตอบใครไม่ได้ และบูตเองไม่ได้ (onboot 0) — ยกเว้นเดียว: ทุก veth อยู่บน vmbr99 ที่ไม่มีทางออก อ่านจาก kernel
D2สำเนาต้นทางต้องมีจริงบนเครื่อง backup และปิดอยู่
D3เลข 9xxx ต้องว่างทั้ง cluster ทั้ง config และ volume
D4 / D5storage ปลายทางต้อง active ไม่อยู่บนดิสก์ระบบ และเช็กเนื้อที่ก่อนจอง
D6เขียน config หลังก๊อปจบดี แล้วอ่านกลับมาเทียบ
D7ไม่เปิดอะไรให้ เด็ดขาด
D8R14 ฝั่ง distribute — lock 9xxx ที่เครื่องปลายทาง ก่อนถาม D3

recall — C

C1หา 9xxx จากการถาม cluster ไม่รับเลขจากคนพิมพ์
C29xxx ต้องปิดก่อน (--final) — ตัวที่รันอยู่คือ service ที่ยังไม่มีใครตัดสินใจหยุด
C3ทิศทางมาจากบันทึกที่มา ไม่ใช่วันเวลาไฟล์ — ไม่มีบันทึก ไม่ทำ
C4presync ต้องรันอยู่ / --final ต้องปิด — ปิดเฉยๆ โดยไม่บอก --final = คนละเจตนา ปฏิเสธ
C5 / C6ปลายทาง mounted=yes และ mount ฝั่งอ่านให้ถูกเจ้าของตามสถานะ CT
C7ไม่เปิด ไม่ปิด ไม่ลบอะไรให้
C8R14 สองปลาย — lock 9xxx ก่อนแล้วค่อย 8xxx

prepare (isolate / evacuate / restore / cleanup) — P E K

P2 / E2ต้องพิสูจน์ก่อนว่า storage ตายจริง — mount ที่ตอบ = ปฏิเสธทั้งยวง ไม่มี override
P4vmbr99 บนเครื่องนั้นต้องไม่มีทางออกจริง ก่อนย้ายอะไรไปลง
P5ไม่เขียนทับบันทึกว่า bridge เดิมคืออะไร
E4ตู้ที่ปิดไม่ลง = isolate แทน ไม่มีการบังคับปิดที่แรงกว่าขอ
K2cleanup ต้องเห็นหลักฐานจาก state ของ failback ว่ารอบ --final จบ ok แล้วจริง
K3ไม่หยุด 9xxx ที่กำลังตอบ ถ้าตัวจริงยังไม่เปิด

คีย์ conf ที่ต้องรู้จัก

conf/ketsync.conf — ของแต่ละเครื่อง ไม่ถูก sync

KS_ROLEmaster / slave — คนเปลี่ยนเองเท่านั้น master คือเจ้าของตาราง
KS_MASTER_IPIP ของเครื่องที่เป็น master ตอนนี้
KS_MAIL_FROM / _INFRA / _NODE / _DIGESTที่อยู่เมลของ watch — ไม่ครบ watch ปฏิเสธ
KS_MASTER_TRIES / _GAPslave ถาม master กี่ครั้ง ห่างกันกี่วิ ก่อนจะเชื่อว่าตาย (3 / 5)
KS_MAIL_RELAY / _USER / _KEYFILErelay ของ provider + login + path ของ key — ketsync mail-setup อ่านสามค่านี้ไปตั้ง postfix เปลี่ยน provider = แก้แล้วรันซ้ำ
KS_WATCH_HEALTHCHECKURL dead-man (healthchecks.io) — รอบเขียวเท่านั้นที่ ping

conf/ctrep.conf — replica / failback / distribute / recall

BKP_SSHroot@<IP เครื่อง backup> — เส้นเลือดหลักของทั้งระบบ
BW_TOTAL_MBเพดาน bandwidth รวมของเครื่องนี้ หารเป็น lane อัตโนมัติ
OFFSET / DR_OFFSET300 → 8300 (สำเนา) และ 300 → 9300 (ตัวชั่วคราว)
MOCKNET_BRIDGEbridge ปิดตาย (vmbr99) ที่สำเนาและตัวที่ถูก isolate ไปอยู่
SHUTDOWN_GRACEเวลารอ shutdown ตอน evacuate/isolate (สั้น เพราะสัญญาณเข้าคิวแล้ว)
SNAP_KEEPเก็บ snapshot รายวันของสำเนาไว้กี่วัน (ค่าที่ให้มาคือ 7) ใส่ 0 = ไม่ทำเลย และการปิดไม่ลบของเก่าที่มีอยู่ทิ้ง

conf/ctrep-exclude.conf — อะไรที่ไม่ก๊อป

บรรทัดละหนึ่ง pattern ของ rsync บรรทัดว่างกับบรรทัดที่ขึ้นต้นด้วย # ไม่นับ replica กับ failback อ่านไฟล์เดียวกัน เพราะทั้งคู่ใช้ --delete กับ rootfs คู่เดียวกัน คนละทิศ — pattern ที่มีผลข้างเดียวแปลว่าไฟล์นั้นไม่เคยถูกก๊อปไปที่สำเนา แล้ววันที่ failback กลับมา มันจะถูก ลบออกจากตัวจริง ไฟล์นี้หาย = ทั้งสองตัวปฏิเสธไม่ยอมรัน ไม่มีการเดารายการให้ ที่ให้มาคือสามบรรทัดเดิม: /tmp/*, /run/*, /var/tmp/systemd-private-* บวก /.zfs ซึ่งไม่ใช่ path ของ container แต่เป็นโฟลเดอร์ควบคุม snapshot ของ dataset ปลายทาง — rsync ไม่ลบสิ่งที่ถูก exclude ไว้ บรรทัดนี้จึงกัน --delete ไม่ให้ไปไล่ลบ snapshot ทั้งก้อนถ้าใครไปเปิด snapdir=visible ส่วน distribute, recall, migrate ใส่ pattern นั้นไว้เป็น flag ในตัว engine เลย ไม่ได้อ่านไฟล์นี้ — เพราะเป็นเรื่องโครงสร้าง ไม่ใช่นโยบายของไซต์ และคำสั่งที่ใช้ตอนเกิดเหตุไม่ควรมีไฟล์เพิ่มให้ปฏิเสธได้อีกไฟล์ เพิ่มได้เฉพาะของที่รู้ว่าคืออะไร ทุก pattern ที่เพิ่ม คือข้อมูลที่สำเนาจะไม่มี

conf/ctmig.conf คือชุดเดียวกันฝั่ง migrate ที่ต่างคือ BW ของมันแยกเพดานกับ ctrep (doctor เตือนเรื่องนี้อยู่จนกว่า conf จะรวมเป็นไฟล์เดียว)

logs/log รายวันของทุกชั้น — dispatcher และ engine ทุกตัว ที่เดียวจบ ชื่อไฟล์บอกคำสั่งกับวันที่ ลบเองหลัง 14 วัน (ของเก่าที่ค้างใน engines/logs/ ย้ายมารวมได้: mv engines/logs/*.log logs/)อ่านอย่างเดียว
state/watch.tsvเรื่องที่ watch ถือค้างอยู่ — ดูผ่าน watch --listระบบเขียนเอง

ไฟล์ .sample คือตัวอย่างที่ git track — ก๊อปแล้วตัดคำว่า sample ออกถึงใช้จริง ตัวจริงของแต่ละไซต์ไม่ถูก track และไม่ถูก git pull ทับ
