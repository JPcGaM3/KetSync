03 จังหวะปกติ เมล 3 แบบ อ่านสถานะ เพิ่ม CT sync + FORKED

03 — งานประจำวัน

cron ทำอะไรเอง เมลจาก watch อ่านยังไง เพิ่ม CT ใหม่ และนิสัยของคำสั่งชุดนี้

ทุกคำสั่งในหน้านี้พิมพ์บนเครื่อง storage (10.100.1.17)
1

จังหวะปกติ — ระบบทำอะไรเองบ้าง

ทั้งหมดอยู่ใน crontab ของเครื่อง storage วันปกติไม่ต้องพิมพ์อะไรเลย

crontab -l # what a healthy master runs
# copy every lane, every 15 minutes
*/15 * * * * /root/ketsync/engines/ct-replica.sh --storage tank-hdd-nas
*/15 * * * * /root/ketsync/engines/ct-replica.sh --storage tank-ssd-nas

# watch the fleet, mail on change
*/10 * * * * /root/ketsync/ketsync watch

# doctor's whole report, once a morning
30 7 * * * /root/ketsync/ketsync watch --digest

บรรทัด replica เรียก engine ตรงๆ (ไม่ต้องมี -y เพราะคำถามอยู่ชั้น ketsync) ส่วน watch เป็นคำสั่งอ่านอย่างเดียว พิมพ์เปล่าๆ ถูกต้องแล้ว

2

เมล 4 แบบ อ่านยังไง

watch ส่งเมลเมื่อมีอะไรเปลี่ยนเท่านั้น — RAISED ตอนปัญหาเกิด CLEARED ตอนหาย ระหว่างนั้นเงียบ ไม่มีเมลซ้ำเรื่องเดิม

เมลแปลว่าทำอะไรก่อน
[ketsync] INFRA ... พื้นที่ทุกอย่างยืนอยู่มีปัญหา — เครื่อง backup เงียบ, PAUSE ค้าง, หรือมี 9xxx อยู่ในระบบ อ่านเนื้อเมล ถ้าเกี่ยวกับ storage ตาย เปิด 05 ทันที
[ketsync] NODE ... เครื่องเดียวมีปัญหา — node ไม่ตอบ ssh หรือ storage ถูกปิดค้างไว้จาก evacuate ssh เข้าไปดูเครื่องที่เมลบอกชื่อ
daily digest รายงาน doctor ทั้งฉบับของเช้านั้น รวมเรื่องราย CT เช่นสำเนาเก่าเกินกำหนด กวาดตาดูหัวข้อที่ไม่ใช่ ok — วันปกติใช้เวลาอ่านไม่ถึงนาที
INFRA: master-unreachable ฉบับนี้มาจากเครื่อง backup ไม่ใช่ storage — แปลว่าเครื่อง storage ไม่ตอบ ssh 3 ครั้งติด และตอนนี้ไม่มีใครเฝ้าฟลีตอยู่เลย เปิด 05 ทันที DR สั่งจากเครื่อง backup

ใครเฝ้าใคร เครื่อง storage (master) เฝ้าทั้งฟลีต ส่วนเครื่อง backup (slave) เฝ้าคำถามเดียวคือ master ตอบมั้ย — เพราะเครื่องที่รายงานฟลีต รายงานความตายของตัวเองไม่ได้ ขอบเขตไม่ทับกัน จึงไม่มีเมลซ้ำสองใบ

ความเงียบก็เป็นสัญญาณ ถ้าใช้ dead-man (healthchecks.io) แล้วมันร้องว่า ping หาย แปลว่าตัว watch เองตาย หรือส่งเมลไม่ออก — ระบบเตือนภัยพัง สำคัญกว่าเมลทุกฉบับที่เคยส่ง เข้าไปดู ./ketsync watch --list ที่เครื่อง storage

3

สามคำสั่งอ่านสถานะ

คำสั่งตอบคำถามว่า
./ketsync statusรอบล่าสุดของแต่ละ CT เป็นยังไง ก๊อปเมื่อไหร่ ติดอะไร
./ketsync doctorตอนนี้อะไรยังไม่ต่อกัน — ตรวจทั้งสองชั้น อ่านบนลงล่างแล้วแก้ทีละอัน
./ketsync watch --listwatch กำลังถือเรื่องอะไรค้างอยู่ (เมลไปแล้ว ยังไม่ CLEARED)

ทั้งสามอ่านอย่างเดียว สั่งซ้ำได้ไม่จำกัด

4

เพิ่ม CT ใหม่เข้าระบบ

  1. เพิ่มแถวใน สองตาราง ที่เครื่อง master — แผนที่ กับ ใบงาน
    $EDITOR conf/fleet.tsv
    # conf/fleet.tsv - the map: ct, home, dr, dst (ALL required, tab-separated)
130	10.100.1.32	10.100.1.32	local-lvm

# inventory/inventory-replica.tsv - the work list: ct + dest pool
130	replica-hdd

    อย่าลืม bump บรรทัด # generation: ของไฟล์ที่แก้ขึ้นหนึ่ง

  2. ส่งตารางไปทุกเครื่อง — ไม่มีอะไรส่งให้อัตโนมัติ
    ./ketsync sync
    ./ketsync sync
  3. ซ้อมตัวเดียว แล้วค่อยของจริง
    ./ketsync replica --dry-run --ctid 130
    ./ketsync replica --dry-run --ctid 130
./ketsync replica --ctid 130

    รอบแรกก๊อปทั้งก้อน รอถึงจบ รอบต่อไป cron เก็บเอง

5

แก้ตารางแล้ว sync เสมอ — และคำว่า FORKED

แก้ตารางที่ master แล้วต้องพิมพ์ ./ketsync sync เอง ถ้าลืม เครื่อง backup ถือรายการของเดือนที่แล้วโดยไม่มีอะไรบอก ที่ส่งคือตาราง 4 ไฟล์ ส่วน .conf กับ nodes.map ไม่ส่งเด็ดขาด (มี KS_ROLE — ส่งไปทุกเครื่องจะคิดว่าตัวเองเป็น master)

เจอ FORKED = สองเครื่องถือ generation เท่ากันแต่เนื้อไฟล์ต่างกัน sync จะหยุดทั้งรอบ เพราะไม่รู้ว่าฝั่งไหนถูก ไล่สามขั้น

./ketsync sync --diff
# 1. read what differs - changes nothing
./ketsync sync --diff

# 2. edit THIS machine's copy until it is the right one
$EDITOR conf/fleet.tsv

# 3. "mine is the one" - one file at a time, then it pushes
./ketsync sync --bump fleet.tsv

ระบุชื่อไฟล์เสมอ — --bump เปล่าๆ ตัดสินทุกไฟล์ที่แตกกันในรอบเดียว ถูกต้องต่อเมื่ออ่าน diff ครบทุกไฟล์แล้วจริงๆ

6

สามนิสัยของคำสั่งชุดนี้

  • คำสั่งเปล่าปฏิเสธ — ./ketsync replica เฉยๆ ไม่ทำอะไร มันพิมพ์เมนูแล้วออกรหัส 2 ต้องบอกขอบเขตเอง (--all / --ctid) เพราะสี่ตัวอักษรที่พิมพ์เพิ่มคือหลักฐานว่าตั้งใจ
  • คำสั่งที่เขียนจะถามหนึ่งครั้ง โดยบอกว่ามันกำลังจะเขียนอะไร ใน cron ต้องมี -y ไม่งั้นปฏิเสธดังๆ (doctor ไล่ crontab เตือนให้เอง ยกเว้นคำสั่งอ่านอย่างเดียวอย่าง watch ที่ไม่ต้องมี)
  • พัก CT รายตัวได้ — สร้างไฟล์ engines/pause/<ctid> แล้ว cron ข้ามตัวนั้นพร้อมบอกเหตุผล ลบไฟล์เมื่อพร้อมกลับมา ส่วน engines/PAUSE (ตัวใหญ่ไฟล์เดียว) หยุดทั้งระบบ ใช้เฉพาะช่วง failback
