01 — What is this

Five minutes: four machines, two layers, three numbers, three iron rules

Read this before everything else. Nothing to type.
1

Four machines

machineIPjob
storage10.100.1.17 owns every CT's raw disk image and runs every engine — the master
backup10.100.1.9 holds the stopped DR copies + PBS, and is where you stand when storage dies
compute10.100.1.32 / .33 run the CTs off NFS-mounted images; nothing installed on them

The storage node stays outside the cluster on purpose — if it voted and then died, the cluster would lose a vote along with the disks. Everything a human types is an IP.

Three numbers nobody types

numberwhatwhere

Every command takes the real id; the rest is arithmetic from two OFFSETs in conf. A leading 9 in pct list means temporary, and somebody owes a cleanup.

4

Three iron rules

  • Nothing starts or stops a container for you. Every tool moves data, writes a config, and prints the pct start for a person to type — bringing a customer's service back is a decision, not a step.
  • A loud refusal beats a quiet success. A GUARD in the log means the system stopped you for a reason it states right there. There is no --force.
  • No defaults, no guessing. A row that forgot a value looks exactly like a row that meant it, so incomplete rows refuse the whole file with a line number.
